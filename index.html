Past papers are PDF-only with complex math notation. Can't directly convert to the required LaTeX format. Third-party OCR tools restricted due to data privacy.

Stage 1: PDF Segmentation

The OCR model can only handle small image segments at a time — not full pages. So we need to break each page down first.

  • Convert each PDF page to an image
  • Vertical segmentation — detect line boundaries, split into rows
  • Horizontal segmentation — separate math expressions from surrounding text
  • Output: ordered folder of small, focused image segments per PDF

Stage 3: Syntax Cleaning

Regex-based post-processing to fix systematic OCR errors

Problem: Math-mode wrapping

this is a normal sentence
↓ OCR converts to ↓
\mathrm{this~is~a~normal~sentence}

OCR wraps plain text in math commands, producing invalid LaTeX

Problem: Delimiter placement

$f(x) is a function$
↓ should be ↓
$f(x)$ is a function.

Math delimiters incorrectly span non-math text

A series of regex replace functions detect and correct these patterns automatically

Known Limitations

🔄

Repetition Artifacts

Expected: This is a sentence,

Got: This is a sentenceThis is a sentence \n This is a sentenceThis is a sentence

Model sometimes outputs multiple copies of the same content. Inherent to the OCR model with no trivial workaround.

⚠️

Conversion Errors

Some mathematical symbols are misrecognized. Distorted or low-resolution source images compound this problem. Manual review still needed for edge cases.

🔎

62% Base Accuracy

Highest available on HuggingFace for LaTeX OCR, but still requires the segmentation and cleaning stages to be usable in practice.

Summary

  • Built an end-to-end automated pipeline converting exam PDFs into structured LaTeX datasets
  • Designed segmentation algorithms to work around OCR model's input size limitations
  • Regex-based cleaning systematically fixes recurring OCR artifacts
  • Enabled evaluation of DeepSeekMath-RL on real university calculus problems
